**SharePoint SE Components Update**  
**Change window: September 8-9, 2026**

**Dynamic Forms** `1.0.0.96`

- Dynamic values and URL parameters can now target writable text, number, Boolean, Date/Time, lookup, and person columns, rather than only lookup columns.
- When **Use dynamic item ID as form item ID** is disabled, `itemid` filters the configured target column instead of incorrectly loading SharePoint item `ID`.
- Added ordered conditional styling and visibility rules.
- Conditional rules support background, text, border, corner radius, font size, and font weight.
- Hidden fields are removed from the layout and no longer trigger required validation.
- Required and targeted validation errors display a red border around the complete field. Configured styling returns when the error is corrected.
- Submit and Cancel destinations can be selected from site pages or entered as custom URLs.
- Redirects can append the saved/current item ID using a configurable query parameter.
- Added same-page Previous/Next wizard navigation.
- Wizard navigation now runs only in preview or published mode.
- Previous-record IDs are preserved independently as users move backward and forward.
- Edit saves use the record actually loaded by filtering and cannot silently fall back to creating a new record.
- Wizard advancement occurs only after SharePoint accepts the save and the saved record reloads successfully.
- Added document-library support:
  - A synthetic required **Document** field is available in the designer.
  - New mode uploads one document and then updates its metadata.
  - Edit mode updates metadata and can replace file content while retaining the filename and item ID.
  - View and Edit modes use SharePoint's document `File` API.
  - Ordinary lists retain their existing multi-file attachment behavior.
- Corrected SharePoint SE document upload failures by explicitly using OData v3.
- Restored visual rich-text editing so saved HTML is rendered rather than displayed as tags.
- Fixed rich-text focus being redirected to the Bold toolbar button.
- Preserved the rich-text caret while parent state updates occur.
- Added a runtime navigation-state contract for Form Navigator, including active, item, mode, dirty, completed, submitting, validation, and permission states.
- Field and attachment changes mark a form dirty; successful saves and authoritative reloads clear that state.
- Moved Form name, Previous form, and Next form directly below Item ID in the property pane without changing their behavior.

**Impact:** Existing list forms remain compatible. Document-library forms require the new Document field and exactly one primary file in New mode. Hidden required fields no longer block submission. Deploy Dynamic Forms before Form Navigator.

**Report Forms** `1.0.0.65`

- Dynamic and URL values can filter supported writable columns instead of being limited to lookup columns.
- Added the same ordered conditional styling and visibility designer as Dynamic Forms.
- Hidden fields reflow the report layout without leaving gaps.
- Embedded List Controls now receive parent values more reliably.
- Parent values can fall back to the incoming dynamic or URL value used to resolve the report.
- Embedded ListControl filters are restored after mount or remount.
- Added a unique **Report name for navigation** setting.
- Report Forms can now be discovered and selected by Form Navigator.
- Report Forms publish active, completed, resolved-item, and error state to the navigator.
- Multiple reports can be shown one at a time through the same scoped navigation used by Dynamic Forms.
- Report navigation does not replace each report's fixed ID, URL, filter, or dynamic-data record selection.
- All reports remain visible while the SharePoint page is being edited.

**Impact:** Existing report layouts remain valid and Report Forms remains read-only. Linked Report Forms and List Controls should be upgraded together. Deploy Report Forms `1.0.0.65` or later before using it with Form Navigator.

**List Control** `1.0.0.90`

- Lookup and person columns now display readable SharePoint values instead of serialized JSON.
- Runtime filters can use hidden support columns that are not present in the selected view.
- Runtime-only support fields remain hidden unless explicitly configured for display.
- Embedded runtime filters are restored after remounting.
- **Link to Item** now supports:
  - Same tab
  - New tab
  - New browser window
  - Resizable in-page dialog
- Dialog resizing no longer causes the dialog to close when the resize handle is released.

**Impact:** Existing same-tab links continue to work by default. Related-record filters no longer require the relationship column to be displayed. Dialog users close with the explicit Close button or the embedded page callback.

**Grid Control** `1.0.0.65`

- Runtime parent filters can use fields not included in the selected SharePoint view.
- Runtime-only support fields remain hidden unless explicitly configured for display.
- Embedded grids restore parent filters, new-row defaults, and mode-based read-only state after remounting.

**Impact:** Parent/child grids remain independently configured, but Dynamic Forms and Grid Control should be upgraded together for reliable embedded behavior.

**Form Navigator** `1.0.0.2`

- Added a new standalone SPFx web part for direct navigation among Dynamic Forms and Report Forms.
- Supports Dynamic Forms-only, Report Forms-only, and mixed form/report navigation on the same page.
- Forms and reports can be grouped into configurable categories.
- Categories and targets use sortable property-pane collections; end users do not edit JSON.
- Target rows provide category and discovered form/report dropdowns, navigation label, required setting, and policy override.
- Supports vertical, horizontal-category, and tree layouts.
- Supports free, completed-only, sequential, and locked-target preview policies.
- Displays active, completed, available, locked, and error states.
- Supports category completion counts and unsaved-change confirmation for Dynamic Forms.
- Automatically activates one configured target when the page loads.
- Initial activation retries briefly when target web parts are still registering.
- Only forms and reports selected in that navigator are hidden or activated.
- Existing `1.0.0.0` JSON configuration is migrated into the collections automatically.
- Includes configurable colors, typography, spacing, indentation, borders, and corner radius.
- Added Form Navigator to the repository build scripts and package publishing workflow.

**Impact:** This is a new package. All coordinated targets must be on the same page and use unique navigation names. Deploy Dynamic Forms `1.0.0.96` and/or Report Forms `1.0.0.65` before Form Navigator. Report Forms remain read-only and retain their own item-selection configuration.

**Build and Deployment**

- Dynamic Forms `1.0.0.96`, Report Forms `1.0.0.65`, and Form Navigator `1.0.0.2` completed clean ship builds and package generation.
- Form Navigator uses `@pnp/spfx-property-controls` `1.13.0`, which provides collection editors while remaining compatible with this repository's SPFx 1.5.1 toolchain.
- The publishing workflow and repository build scripts now include Form Navigator.
- Component README files and the root component catalog were updated for the new behavior and deployment requirements.

**Impact:** Deploy dependent controls first, then Dynamic Forms and Report Forms, and deploy Form Navigator last. After upgrading, edit each target page, assign unique navigation names, configure the navigator collections, publish, and test navigation in page read mode.
